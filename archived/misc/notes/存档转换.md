这份备忘录将指导你如何利用 mGBA 自带的转换工具处理带有实时时钟（RTC）数据的绿宝石存档，使其能够被 VBA 识别并配合 Pokemonmemhack（内存修改器）使用。

### **备忘录：绿宝石存档跨模拟器转换流程（mGBA 至 VBA）**

#### **1. 准备工作**
*   **确保存档最新**：在 mGBA 中运行游戏，进行一次正式的“党内保存”（Save），建议保存两次以确保数据完整写入 [1]。
*   **确认文件大小**：mGBA 生成的带 RTC 数据的绿宝石存档通常为 128.02 KB 或 129 KB，而 VBA 要求的标准 Flash 存档必须精确为 128 KB (131,072 字节)。

#### **2. 使用 mGBA 转换工具截断存档**
mGBA 的开发版本（Dev Builds）及较新正式版内置了专门的转换功能，可以自动剔除末尾的 16 字节 RTC 页脚 [2, 3]。
1.  启动 **mGBA** 模拟器。
2.  点击顶部菜单栏的 **文件 (File)** -> **保存游戏 (Save Games)** -> **转换保存游戏 (Convert Save Game...)** [2]。
3.  在弹出的窗口中选择你当前的 mGBA 存档（.sav）。
4.  该工具会自动处理并导出一个“干净”的 128 KB 存档文件。请将其重命名为方便识别的文件名（例如 `Emerald_Clean.sav`）。

#### **3. 将存档导入 VBA**
1.  启动 **Visual Boy Advance (VBA)**。
2.  首先通过 **File -> Open** 加载你的绿宝石 ROM 镜像。
3.  点击 **File -> Import -> Battery file...** [4, 5]。
4.  选择你在第 2 步中转换好的 128 KB 存档。
5.  模拟器会提示重置游戏，点击确定。此时你应该能看到游戏成功读取了之前的进度。

#### **4. 运行 Pokemonmemhack**
1.  保持 VBA 处于游戏运行状态（不要暂停）。
2.  启动 **Pokemonmemhack**。
3.  点击修改器界面上的 **“刷新”** 或自动识别按钮。由于存档现在已经符合 VBA 的标准内存映射，修改器应该能够正常读取到 0x02020000 附近的宝可梦数据。

#### **5. 故障排除（如果转换工具不可用）**
如果你使用的 mGBA 版本没有转换选项，可以采用 **HxD 十六进制编辑器** 手动修复：
1.  用 HxD 打开原始存档。
2.  滚动到文件最末尾。
3.  选中从偏移量 `$20000`（即第 131,072 字节）开始的所有多余数据（通常是 16 个字节的 RTC 偏移量） [6]。
4.  按 **Delete** 删除，保存文件。
5.  确认文件属性显示大小正好为 128 KB 后，再次尝试导入 VBA [6]。

---
**注意**：在 VBA 中修改完成后，如果想将存档导回 mGBA 继续游玩，只需在 mGBA 中直接读取该 128 KB 文件即可，mGBA 会在下次存档时自动重新补回 RTC 页脚以维持时间同步。
